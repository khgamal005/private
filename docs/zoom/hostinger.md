## ما تحقق وما تعذر

نجحت بوابة CI على هذا SHA: **1652 نجاحًا، صفر فشل، 3 اختبارات مشروطة متجاوزة، من 1655**. جميع اختبارات Zoom الخمسين نجحت، ومنها تنافس اتصالين حقيقيين على PostgreSQL17. نجح lint مع19 تحذيرًا قائمًا دون أخطاء، وفحص الأنواع و292 ترحيلًا والبناء. [الأدلة المفصلة](evidence/review-faf3b1d.json) و[سجل CI](https://github.com/Marktonesa/marktone-platform-control/actions/runs/35848578656).

فُتحت `https://hpanel.hostinger.com/` للقراءة فقط، لكنها بقيت في شاشة Cloudflare «Performing security verification». لم يظهر الحساب أو الموقع أو الخطة أو ربط GitHub؛ لم تُدخل بيانات اعتماد، ولم يُتجاوز التحقق الأمني. لا يوجد موصل Hostinger قابل للاستدعاء في الجلسة. لا ادعاء بأن الإضافة نُفذت على مضيف هوستينجر بالفعل.

## نقطتا عزل يجب حسمهما قبل أول بناء مستضاف

1. [lib/config.js](../../lib/config.js) يختار قاعدة الإنتاج الافتراضية `gswpbwdactcstkasddta` إذا غابت المتغيرات. غياب `VERCEL_GIT_COMMIT_REF` على هوستينجر **لا ينشئ عزلاً تلقائيًا**. سجل project ref المأذون ومطابقة متغيرات البناء والتشغيل قبل أي بناء/تشغيل. مفاتيح anon/publishable لا تحول قاعدة الإنتاج إلى قاعدة اختبار. لا تعِد استخدام قواعد معاينات أخرى اعتمادًا على اسم الفرع، ولا بيانات ريف.
2. [support-request-origin](../../lib/support-request-origin.mjs) يجيز حاليًا `odeir.com` و`www.odeir.com` و`staging.odeir.com` عبر HTTPS بلا منفذ مخصص، مع مطابقة Host/forwarded host/origin. نطاق Hostinger المؤقت لن يسمح بطلبات التدريب وZoom المعدِّلة بمجرد أن الصفحة ظهرت. يلزم نطاق تجربة مأذون وبيئة معزولة متحققان، أو تغيير محدود ومختبر للقائمة بعد معرفة النطاق. لا wildcard ولا تعطيل فحص origin ولا إضعاف cookies/CSRF. وجود `staging.odeir.com` بالقائمة ليس إذنًا لاستخدام موقعه أو بياناته القائمة.

لا تضع أسرار Zoom على هوستينجر لتجاوز غياب Edge. استمر بإعدادات Supabase الخادمية الموجودة للوظائف الأخرى دون تبديلها أو نسخها إلى المتصفح. بالنسبة للذكاء، تبقى مفاتيح Odeiry وموازنته وإذن معالجة التفريغ منفصلة كما في [runbook](runbook.md).

## الربط الخارجي وجدولة العامل بعد الإذن

| المكوّن | العنوان / التحقق المطلوب |
|---|---|
| OAuth callback | `https://<approved-origin>/api/zoom/callback`؛ مطابق حرفيًا لـ`ZOOM_REDIRECT_URI`، وأصله يطابق `ZOOM_PUBLIC_ORIGIN` |
| Webhook | `https://<approved-project>.supabase.co/functions/v1/zoom-connect/webhook`؛ جسم خام وتوقيع وتوقيت وتخزين قبل الإقرار |
| جدولة Zoom | POST إلى `/functions/v1/zoom-connect/dispatch` مع `x-odeir-zoom-dispatch` خادميًا؛ سر منفصل، ليس query ولا ملفًا عامًا |
| وتيرة البداية | كل دقيقة ضمن منظومة تشغيل مأذونة؛ لا cron أُضيف بالفعل. قس التأخر والميزانية قبل زيادة العمال |
| معالجة الإيقاف | dispatch يستطيع معالجة أدلة واردة وطلبات purge حتى مع flag مغلق؛ إغلاق flag ليس حظرًا لكل الكتابات، ولذلك لا توجه العامل إلى قاعدة حية للاختبار |
| الرسائل | تحقق من أصل الرابط والقناة والموافقة والإصدار باستخدام العامل القائم قبل إذن إرسال منفصل |
| الإطار المضمّن | تحقق من headers النهائية على `/zoom/embed` عبر proxy؛ اختبار صوت/فيديو/مشاركة وجوال مطلوب ولا تثبته JWT أو CI |

لا تنقل قاعدة PostgreSQL إلى MySQL هوستينجر؛ الجداول وRPC وRLS وVault والأدلة تبقى في Supabase المعتمد. لا تشغّل ترحيلات أو seed أثناء build/start.

## بوابة أودير للمضيف

القرار: **التهيئة متوافقة على مستوى المصدر، والقبول على هوستينجر معلق**. الأثر على المخطط صفر لهذه المتابعة؛ ترحيلات Zoom الأربع والعشرون ما زالت إضافية وغير مطبقة بعيدًا. صعوبة إعداد المضيف3/10 إذا كانت خدمة Next.js قائمة، وتزيد مع VPS جديد أو تغيير proxy/نطاق؛ تعقيد التكامل الأصلي9/10 كما في [discovery](discovery.md).

قبل الإجراء الخارجي، ثبّت هوية الموقع والخطة والنطاق والفرع المتصل وإعدادات النشر التلقائي ووجهة Supabase ونسخة الرجوع، دون تغييرها. الربط الأول بالمستودع وتغيير المستودع وDatabase Connect Wizard قد يبدؤون نشرًا تلقائيًا؛ دفعات الفرع المرتبط تعيد النشر أيضًا. ليست هذه إجراءات اكتشاف للقراءة فقط. لا تربط فرع العمل ولا ترفع ZIP إلى الموقع قبل إذن التجربة/الإصدار المحدد. منع Vercel في `vercel.json` يخص Vercel وحده.

بعد إذن بيئة اختبار اصطناعية محددة، يكون ترتيب التحقق:

1. مطابقة schema/RLS/Vault والوجهة، والتحقق من النسخ والاسترداد، ثم تطبيق الإضافات مع الطرح مغلقًا؛ لا backfill عام.
2. نشر المستقبل والعامل، ثم تطبيق Next.js على الموقع المأذون؛ تسجيل SHA وإصدار Node والوقت وأوامر البناء/التشغيل دون أسرار.
3. تحقق دخول مستخدمين اصطناعيين من منشأتين، learner/instructor/operator، وعزل tenant IDs وACL بعد سحب الصلاحية، ومنع origin أجنبي.
4. تحقق من headers ومنع cache للمحتوى الخاص والتصدير، وcookies وHTTPS وHost، ورفض رابط تقرير من مستخدم آخر. نجاح صفحة login ليس نجاح المسار.
5. تنفيذ T-matrix المأذونة بحسابَي Zoom تجريبيين ورخص فعلية؛ تتبع UI→API→SQL→العامل→المزود→Webhook→دليل معتمد. لا بيانات حقيقية أو إرسال مدفوع دون إذن نطاقهما.
6. قياس queue/backoff ومدة التقارير وذاكرة المضيف، وتجربة تعطيل/رجوع تطبيق وعامل متوافقين مع حفظ التاريخ؛ لا حذف جداول أو تسجيلات أو اجتماعات قائمة للتراجع.

التراجع لا يعتمد على استمرار احتفاظ المضيف تلقائيًا بإصدار قديم؛ احفظ مرجع الكود وإعدادات البيئة والسياسة قبل الإجراء. لا تبديل DNS أو حذف موقع قائم ضمن تجهيز Zoom.

## مرجع الاستكمال
