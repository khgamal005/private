المرجع الوحيد: `Marktonesa/marktone-platform-control`، المصدر قبل تعديل قفل runtime: `23735f649d8cde15c83e9475e701d26eee699aa9`. مشروع الإنتاج `gswpbwdactcstkasddta`. لن يُستعمل CRM أو مستودع staging.

## بوابة التنفيذ
- نسخة Physical مدرجة للاستعادة في لقطة المستخدم بتاريخ 2026-09-23 04:47:32 UTC، main PRODUCTION. لم تُجرّب استعادة فعلية؛ Storage غير مشمول.
- 446 سجل migration قبل التنفيذ؛ Zoom الجديد غير موجود. التبعيات الخارجية 39 علاقة/20 دالة موجودة بالأسماء. روجعت تواقيع Vault مع defaults، وأجسام وACL دوال الحضور والأهلية وعدم قابلية المحتوى المنشور للتعديل.
- ملفات الترحيل الـ24 مطابقة ببصمة Git لـmain؛ لا تعديل محتواها، ولا دفع تاريخي شامل. الحزمة تضيف مخطط Zoom وصلاحياته، وتضيف triggers وتغليف أهلية التدريب؛ لذلك تحفظ الدوال الأصلية وتختبر حالات غير Zoom.
- tests/zoom-disabled-rollout.test.mjs: جميع الترحيلات في قاعدة اصطناعية؛ لا وصول منشأة أخرى، لا OAuth عند الإغلاق، أهلية غير Zoom مطابقة للأصل.
- تغيير أمان Edge محدود: `ZOOM_RUNTIME_ENABLED` يمنع كل المداخل قبل RPC أو provider. يظل إيقاف V1 وحده متاحًا لمعالجة الاحتفاظ بعد التفعيل.
- 12 اختبارًا موجهًا ناجحًا، 0 فشل/skip: provider 8، runtime gate 3، closed SQL rollout 1. جميع البيانات اصطناعية محليًا. بوابة CI الكاملة السابقة ناجحة على4e10654a؛ نتيجة قفل runtime الجديد تُسجل عند اكتمال CI.
- لا اختبار تغيير سجلات إنتاجية. التحقق البعيد بعد النشر يكون metadata/ACL ورفض غير المخول وحالة الإطلاق المغلق. الاختبار اليدوي بجلستك الحالية مطلوب لتأكيد واجهة الحسابات.

## خطة التطبيق المقيدة
1. تطبيق الـ24 ترحيلًا بالترتيب، كل ملف مع معاملته وبحد lock_timeout=3s وstatement_timeout=45s؛ إعدادا الجلسة لا يغيران منطق المصدر. التوقف عند أول فشل، ثم فحص ledger قبل أي إعادة.
2. تسجيل version الفعلي واسم الملف وGit blob. لا إعادة كتابة سجل الترحيلات ولا نسخ بيانات بين قواعد.
3. فحص RLS/GRANT والمخطط والـsnapshot والقيود وأعداد صفوف Zoom فقط. التحقق أن الإعدادات المفعلة والحسابات والمهام الجديدة صفر.
4. نشر zoom-connect بقفل runtime مغلق، ثم طلبات HTTP بلا بيانات للتحقق من503 وعدم أي عمل خارجي.
5. لا cron أو أسرار Zoom أو تغيير ترخيص منشأة ضمن التجهيز. عامل الرسائل الحالي يُراجع منفصلًا قبل نشره لأنه يخدم عمليات قائمة؛ لا تشغله للاختبار.
6. توثيق النتيجة الفعلية والموانع الخارجية؛ نجاح البناء لا يكفي للقبول.

## التراجع
إغلاق runtime والجدولة يحفظ البيانات والأدلة. ترحيلات Zoom تبقى إضافية وإعدادات المنشآت غير مفعّلة. لو ظهرت مشكلة في مسار تدريب قائم: أوقف التطبيق التالي، استعمل تعريفات guard الأصلية المحفوظة في أدلة النشر لترحيل تصحيحي محدد بعد التحقق، وأعد إصدار التطبيق المتوافق. لا DROP أو restore شامل تلقائي أو حذف سجلات عميل. استعادة النسخة الكاملة تحتاج قرارًا منفصلًا لأنها تمس كل العمليات منذ وقتها.

## حالة التنفيذ المتحققة

- نجحت الترحيلات الـ24 كلها؛ ledger ارتفع من446 إلى470، بأسماء Zoom وبنسخ التنفيذ الفعلية المسجلة في [الأدلة](evidence/production-migrations-2026-09-23.json).
- 32 جدولًا، RLS على الجميع، ولا SELECT/INSERT/UPDATE/DELETE مباشر لـanon/authenticated/service_role. 101 دالة RPC؛ snapshot للمخوّلين فقط. الدالة العامة الوحيدة لمعاينة دعوة تعتمد token hash صالحًا ودعوة معلقة غير منتهية وترخيص/تفعيل المنشأة؛ الدعوة الاصطناعية غير الصالحة أعادت null.
- نجاح snapshot حسابات ماركتون الفعلي تحت عضوية موجودة مخولة داخل transaction للقراءة فقط: enabled=false، accounts=0، hosts=0. لا جلسة متصفح أو رمز دخول مستخرج. نجح رفض غير المخول ورفض دالة العامل للمستخدم العادي.
- نجح تشفير وفك وتدوير قيمة Vault اصطناعية داخل transaction انتهت بـROLLBACK؛ أُكد أن عدد canary secrets المتبقية صفر. لم تُقرأ قيمة سر قائم.
- zoom-connect منشورة version1 بالقفل مغلق؛ POST start/webhook/dispatch أعاد503 zoom_not_enabled. لا accounts/links/operations/settings مفعلة.
- روجع الفرق مع عامل التدريب المنشور18: دعم رسائل Zoom، منع fallback المركزي للرسالة المدارة، منع fallback template غير المناسب، idempotency لمزود البريد، وتحديث انتهاء token القديم. عدّ الوظائف الحالية المتأثرة بمنع legacy الجديد=0. نجح اختبار تشغيل كود العامل نفسه بتبعيات HTTP اصطناعية: تسليم legacy، رفض Zoom المغلق، رفض غياب مزود المنشأة، استخدام المزود المحدد، واستمرار طابور automation العام. لم يُستدعَ إرسال حي للاختبار. نشر تحديث العامل ما زال ينتظر التسجيل في المتابعة النهائية.
- فُصلت أسرار General OAuth إلى ZOOM_OAUTH_CLIENT_ID/ZOOM_OAUTH_CLIENT_SECRET دون fallback إلى أسماء S2S القديمة التي يستعملها العامل القائم؛ الاختبار يثبت عدم استهلاك بيانات الربط القديم.
- advisors: 32 ملاحظة INFO إضافية لجداول RLS الداخلية بلا سياسات/بلا منح مباشر؛ والتحذيرات العامة عن SECURITY DEFINER ارتفعت1للـanon و45للـauthenticated وفق RPC المعتمدة أعلاه. لا search_path غير آمن جديد؛ لا يُقال إن التحذيرات العددية لم تزد.
