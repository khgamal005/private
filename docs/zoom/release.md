## شروط ما قبل أي إذن إصدار

1. أحدث main وSHA المراجعة، diff المخطط والدوال والصلاحيات والتبعيات، وفحوص ODEIR على كود التسليم.
2. نجاح الاختبارات الحاسمة SQL/HTTP والعزل واتصالَي PostgreSQL، لا البناء وحده. ربط matrix بالأدلة وبيان حالات عدم الاكتمال.
3. حسم سياسة المشتقات والنسخ الاحتياطية ووجهة الإنتاج. إعداد تطبيق Zoom وحسابات اختبار معزولة، scopes/rخص، ومراجعة SDK عند استعماله.
4. تجربة حية محدودة **بإذن منفصل**: حسابان، توزيع، بدء/دخول، تسجيل فردي وإبطاله، عدة إعادة دخول، تقارير وتسجيل، تأخر أحداث وتعطيل اتصال، SDK صوت/فيديو/جوال عند إتاحته. لا تحميل أو إرسال بيانات Reef.
5. إذن صريح منفصل للدمج، وآخر للنشر/التفعيل بحسب ما يحدده المستخدم. وجود PR أو CI أخضر لا يحقق هذا الإذن.

## خطة نشر مقترحة بعد الإذن فقط

تحقق نسخة احتياطية قابلة للاستعادة؛ طبق المخطط الإضافي مع الطرح مغلق؛ انشر المستقبل والعامل ثم التطبيق المتوافق؛ اضبط scheduler وقنوات المنشأة؛ تحقق health للـSHA والمخطط والـworker والوجهة؛ فعّل لمعرف منشأة مأذون واحد؛ نفذ smoke/أدلة المالك والمدرب والمتدرب؛ راقب backlog/429/uncertain/مراجعات الحضور قبل أي توسيع. لا backfill عام، لا نقل اجتماعات قائمة لحساب مركزي، لا تغيير بيانات ريف.

## التراجع

المفتاح العام ZOOM_V1_ENABLED=false يوقف مزايا المزود/الأوامر الخارجية؛ تعطيل إعداد المنشأة/استحقاق الإضافة يمنع الأوامر الحساسة في SQL. لا تكتفِ بإخفاء الواجهة. أبق استقبال الأحداث وتنظيف إلغاء التفويض بالحد المسموح؛ dispatch يعالجها قبل فحص flag. أوقف/اعزل طوابير المزود المتأثرة مع حفظ الحجوزات غير المحسومة. رجوع التطبيق لإصدار متوافق لا يحذف جداول أو مراجع جديدة. لا DELETE/DROP عكسي، ولا reset/force push، ولا إلغاء اجتماعات حية أو تسجيلات أصلية كجزء من rollback.

عند الرجوع إلى كود قديم أبق حواجز البيانات الجديدة وخطة تسوية عمليات Zoom؛ العامل القديم لا يتبنى حسابًا مركزيًا لمنشأة جديدة. عدم عرض واجهة Zoom لا يعني حذف حضورها أو دفعها. تراجع التطبيق/Edge الكامل في بيئة نشر فعلية **لم يُجرب** ويجب أن يكون جزءًا من الإذن المحدود.

## المخاطر والحدود المفتوحة

| المعرّف | الخطر/الفجوة | القرار الحالي/شرط الإغلاق |
|---|---|---|
| R01 | لم يُستخدم حساب Zoom حي | عقود اصطناعية فقط؛ حسابات ورخص وإذن تجربة مطلوبة |
| R02 | SDK خارج حساب التطبيق | fallback؛ المراجعة وZAK/OBF حسب المسار واختبار T55 قبل الادعاء بالتضمين العامل |
| R03 | حذف مشتقات AI/نسخ احتياطية | policy_required، مانع تفعيل خارجي حتى سياسة ومسار تنظيف متحقق |
| R04 | وجهة الإنتاج الفعلية | مانع نشر حتى إثبات project/host/domain/worker وSHA |
| R05 | لقطة مضيف/رخص/انشغال ناقصة | سعة محافظة وتغطية معلنة؛ لا ضمان منع تعارض غير مرئي |
| R06 | نجاح كتابة Zoom وفقد ردها | حجز محفوظ وuncertain؛ لا إنشاء أعمى؛ الإلغاء القديم غير المحسوم يحتاج قراءة/مراجعة مزود |
| R07 | 3000 منشأة اصطناعية | دليل DB workload فقط، لا 3000 محاضرة متزامنة أو أداء شبكة/مزود |
| R08 | تقرير حضور/تكلفة ناقص | quality/null/تغطية بدل صفر كاذب؛ لا فواتير/ROI من حضور ندوات |
| R09 | أمثلة اليوم7/8 في المواصفة | مصدر الحقيقة المالي الأحدث مقدم: لا تعليق تلقائي لمقبول بسبب متأخرات لاحقة |
| R10 | UI لا يساوي وصول شامل | 360/390/768 ولوحة مفاتيح مثبتة محليًا؛ قارئ شاشة ووسائط SDK حيًّا غير مختبرين |
| R11 | وظائف التقرير المتقدمة | مقارنة الفترات ونتائج التقييم الأكاديمي منفذة؛ تقييم الطلاب للمدرب بلا مصدر قائم متحقق، ولا استنتاج جودة تدريس من دقائق Zoom |
| R12 | إعداد الفروع/القاعات | منع تعارض الإنسان والمضيف مثبت؛ نطاق الفرع متصل بـcore.branches ومختبر؛ فحص قبول تعارض قاعة hybrid نجح عبر الجدول القائم، ولا جدول قاعات ثانٍ |

لا إصدار عند إخفاق عزل/سر/استحقاق/شهادة/ازدواجية حرجة/فقد تاريخ/تجاوز رخص أو غموض وجهة. لا تخفيض لاختبار حرج لكي يصبح CI أخضر.
