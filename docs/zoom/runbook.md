# إعداد Zoom ودليل التشغيل

هذا دليل تجهيز ومراجعة. **لا ينفذ نشرًا أو تفعيلًا ولا يمنحهما الإذن.** تاريخ مرجع Zoom 2026-09-22؛ إعادة فحص manifest واجبة عند إعداد تطبيق حقيقي.

## التجهيز المغلق والتراجع

تبقى `ZOOM_RUNTIME_ENABLED` غائبة أو `false` أثناء تجهيز الإنتاج. لا تعيّنها `true` قبل إعداد التطبيق والأسرار والتحقق من البيئة وإذن التفعيل المستقل. هذا قفل شامل لكل المداخل؛ لا يغيّر بيانات أو إعدادات المنشآت. بعد التفعيل، يمكن إيقاف `ZOOM_V1_ENABLED` فقط لإيقاف طلبات المزود مع السماح بمعالجة الأدلة/الاحتفاظ المصادق عليها. للإغلاق الكامل مجددًا أوقف `ZOOM_RUNTIME_ENABLED` وأوقف الجدولة. لا تحذف جداول أو صفوف للتراجع.

## مسؤول الإعداد

1. حدد بيئة تجريبية منفصلة بمخطط مطابق وبيانات اصطناعية، ثم حسابَي Zoom مستقلين مصرحين للاختبار. لا تستخدم ريف أو بيانات متدربين حقيقيين.
2. أنشئ General OAuth admin-managed في Zoom Marketplace. سجل callback ثابتًا `https://<authorized-origin>/api/zoom/callback` مطابقًا حرفيًا لـZOOM_REDIRECT_URI. أصل الإرجاع ثابت؛ لا redirect يرسله المستخدم. لا أسرار في query أو NEXT_PUBLIC.
3. اضبط scopes المقابلة فقط للقدرات المطلوبة في [manifest](manifest.md)، واشترك في الأحداث الواردة فيه. حساب ناجح التفويض لا يثبت سعة التسجيل/الندوات/التزامن. افحص ما منحه المزود فعلًا وأعد التفويض عند تغييره.
4. اضبط Webhook على Edge endpoint، مع سر تحقق منفصل لكل بيئة. اختبر URL validation وإعادة التحقق والتكرار وحفظ الحدث ضمن مهلة المزود في البيئة المأذونة.
5. ثبّت العامل المجدول ضمن منظومة التشغيل المعتمدة بعد إذن الإصدار. يستدعي POST `/functions/v1/zoom-connect/dispatch` مع `x-odeir-zoom-dispatch` من سر العامل. دعوة كل دقيقة نقطة بدء محدودة، وليست سعة مقاسة؛ راقب backlog وغيّر عدد العمال/الوتيرة ضمن ميزانية Zoom المقاسة. ليس cron مسجلًا تلقائيًا في الإنتاج.
6. شغّل `training-automation-dispatch` الحالي للرسائل مع إعداد قناة المنشأة وZOOM_PUBLIC_ORIGIN نفسه. مسار Zoom الجديد يرفض fallback لمزود مركزي. لا تفعّل S2S القديم لمنشآت جديدة؛ معالجة اعتماد قديم تحتاج قائمة أثر وإذنًا مستقلًا.
7. SDK خيار منفصل: Meeting SDK credentials ومراجعة حسابات خارجية ومسار هوية المستخدم وفق Zoom. لا تضع REVIEWED=true دون دليل مراجعة. لا يعوض JWT عن ZAK/تفويض مطلوب. جرب الصوت والكاميرا والمشاركة والعودة والجوال بهوية مضيف وطالب مأذونتين. غير ذلك يستعمل الدخول الخارجي.
8. AI: إعداد Odeiry القائم وميزانيته وسياسة معالجة التفريغ وموافقة بشرية. لا اتصال مدفوع أو إرسال تفريغ قبل ذلك. تطبيق مسودة LMS يخضع لتفعيل LMS ونطاق authoring القائمين بصورة مستقلة.

## المتغيرات — أسماء فقط

| الموضع | المتغير | المالك والغرض |
|---|---|---|
| Edge | SUPABASE_URL / SUPABASE_ANON_KEY / SUPABASE_SERVICE_ROLE_KEY | البنية؛ خدمة منفصلة عن المتصفح |
| Edge | ZOOM_OAUTH_CLIENT_ID / ZOOM_OAUTH_CLIENT_SECRET | مالك General OAuth؛ مستقلان عن ZOOM_CLIENT_ID/ZOOM_CLIENT_SECRET للربط S2S القديم؛ لا fallback |
| Edge | ZOOM_REDIRECT_URI / ZOOM_PUBLIC_ORIGIN | مسؤول البيئة؛ HTTPS ثابت متطابق |
| Edge | ZOOM_WEBHOOK_SECRET | مالك اشتراكات الأحداث |
| Edge + scheduler | ZOOM_DISPATCH_SECRET | سر العامل، ليس مفتاح مستخدم |
| Edge | ZOOM_ENVIRONMENT | test أو production؛ مطابق إعداد اتصال المنشأة |
| Edge | ZOOM_RUNTIME_ENABLED | قفل الإطلاق العام؛ غائب/false يمنع جميع المداخل قبل أي RPC أو اتصال مزود، بما فيها webhook وdispatch |
| Edge | ZOOM_V1_ENABLED | تشغيل المزود؛ مغلق/غير موجود افتراضيًا. بعد فتح قفل runtime فقط، إيقافه يبقي معالجة الأحداث والاحتفاظ المصادق عليها متاحة |
| Edge | ZOOM_SDK_ENABLED / ZOOM_SDK_REVIEWED | مغلقان افتراضيًا؛ الثاني حقيقة مراجعة خارجية |
| Edge | ZOOM_SDK_APP_ACCOUNT_ID / ZOOM_SDK_CLIENT_ID / ZOOM_SDK_CLIENT_SECRET | حساب التطبيق وهويته؛ خادميًا فقط |
| عامل الرسائل | ZOOM_PUBLIC_ORIGIN | أصل روابط المحاضرات، يرفض الغياب/HTTP/بيانات دخول ضمن URL |
| التطبيق | إعداد Supabase الحالي | reuse للـcookies/JWT، لا Zoom secret أو host URL عام |
| قاعدة البيانات | Supabase Vault | إدارة إصدار/تدوير مفتاح تشفير البنية وفق إجراء Supabase؛ لا مفتاح تشفير ثانٍ مخترع في الإضافة |

## المالك والموظف

من إعدادات الإضافة: اربط حسابًا ثم «حسابًا إضافيًا». إعادة الربط تخص الحساب نفسه. زامن المضيفين، راجع التغطية والسعة والتاريخ، اسمح بالمضيف واربط المدرب وتحقق من هويته لدى Zoom. حدد الهوامش وفترات عدم التوفر والتفضيل. أضف مالك متابعة فعّالًا في المنشأة؛ إن لم يعين تبقى المهام غير مسندة بصورة صريحة.

من شاشة تشغيل المتدربين: حدد المحاضرة والمدرب والعدد والنوع. ابدأ بمعاينة التوزيع ثم احفظ. اليدوي يمر بالشروط نفسها. الدفعة تعرض نتيجة كل جلسة؛ أكمل المتعارضات ولا تعتبر بعضها نجاحًا للجميع. الاجتماعات المستقلة هي الافتراضي. السلسلة المنتظمة اختيار صريح؛ استيراد وقعة يتطلب occurrence_id ثابتًا وحسابًا ومضيفًا ومواعيد مطابقة. «قراءة فقط» لا يمنح حق تعديل مستورد.

للتأجيل أو التعديل راجع النسخة والأثر على الحجوزات والتذكيرات. «غير مؤكد» يستلزم تحقق المطابقة؛ لا تنشئ ثانيًا لمعالجة timeout. «اختلاف» يعرض الموعد المرصود، ثم يقرر المخول إجراء التحديث المقصود. الاستبدال بين حسابين يحتاج إقرار أثر وسبب واجتماعًا لم يبدأ؛ لا يعد بحفظ رابط Zoom القديم. الإلغاء لا يحذف الحضور أو يعكس الدفع.

بعد الانتهاء راجع النافذة والاستراحات وسياسة البرنامج والأسماء غير المطابقة، ثم اعتمد الحضور. تعديل يدوي يحتاج سببًا وثواني معتمدة عند احتسابها. انتهاء الاجتماع أو فتح التسجيل ليس إكمالًا. راجع مهام نقص الساعات والتأخر والغياب المكتمل والتداخل وشهادة تغيّر دليلها.

التسجيلات تبدأ قيد المراجعة. اعتمد سياسة المدة وحدود رابط Zoom ثم انشر المحدد، أو اسحب إتاحته. التقارير تتيح الفلاتر وCSV الصفحة الحالية أو مهمة تصدير كامل محدود؛ رابط التصدير مؤقت ومربوط بمستخدمك.

## المدرب والمتدرب والمبيعات

المدرب يستخدم محاضراته المسندة وهوية فعلية؛ لا role preview. زر البدء يظهر حسب التفويض الحالي ويعاد فحصه. الغرف الفرعية داخل عميل Zoom إن دعمتها الخطة؛ الاستطلاع الذي ينشئه أودير طلب فعلي وليس اختبارًا أكاديميًا تلقائيًا.

الطالب يدخل بالدعوة/الحساب الحالي إلى `/training/<slug>/zoom` ثم صفحة المحاضرة. يكمل البريد ويتحقق منه. تظهر حالة الموعد والاستحقاق، حضوره الشخصي والتسجيلات المنشورة. لا عضوية موظف لازمة ولا LMS مفروض. الاقتراض أو تأخر القسط يعالجه مسار أودير المالي الحالي؛ لا تُكرر التحصيل بسبب Zoom.

المبيعات تضبط الندوة المرخصة ومصدرها وحملتها وموافقة التسجيل/التسويق، وتختار العميل ضمن نطاقها. التسجيل المتكرر يعيد ملف CRM. «إرسال بيانات الانضمام» يمر بالقناة الحالية ويعيد فحص المستلم والموافقة. لا تحويل تلقائي إلى طالب مدفوع أو إيراد. لا يوجد إرسال خارجي في اختبارات هذه الحزمة.

## استجابة الأعطال

- 401: إعادة تفويض الحساب المعني؛ لا فحص أسرار في السجلات.
- 403: تحقق scope/الترخيص للقدرة المعنية؛ لا زيادة سعة من واجهة يدويًا.
- 429: cooldown/backoff وRetry-After؛ لا نقر متكرر أو تجاوز ميزانية العامل.
- timeout بعد كتابة: عملية غير مؤكدة وحجز محفوظ؛ مطابقة مزود أولًا، ثم تدخل مخول عند الغموض.
- تقرير مؤقت بصفر/خروج مفقود: بيانات ناقصة؛ انتظر التصالح أو راجع، لا اعتماد غياب آلي.
- رابط تسجيل مسحوب: يمنع الإصدار اللاحق من أودير؛ الرابط الأصلي السابق يخضع لضوابط Zoom.
- إلغاء تفويض: راجع purge_requests/retention_runs والمهام؛ لا تعلن اكتمال الحذف بينما policy_required أو سياسة النسخ الاحتياطية معلقة.
